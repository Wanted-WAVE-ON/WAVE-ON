# Q&A

## 무엇을 학습하나요?

명령을 몸짓에 미리 고정하지 않고, 몸짓 뒤의 사용자 행동을 활동별로 집계해 승인된 기억을 만듭니다. 고정 특징과 통계 기반이며 신경망·자유 몸짓 학습은 아닙니다.

## 행동과 맥락을 직접 고르는 설정 화면 아닌가요?

웹 UI와 라벨 모드는 시뮬레이션입니다. Windows 관측 모드는 몸짓 뒤 같은 앱에서 실제로 누른 첫 허용 키를 연결하고 활성 앱으로 발표·음악을 판정합니다.

## 세 번만 반복하면 안전한가요?

세 번은 데모 임계값입니다. 승인 전에는 실행하지 않고, 낮은 점수·낮은 유사도·상충 Intent는 보류합니다.

## 개인정보는 어떻게 보호하나요?

프레임은 메모리에서 처리한 뒤 폐기하며 저장·업로드하지 않습니다. 얼굴·신원 특징과 일반 키 문자열도 저장하지 않습니다.

## 같은 몸짓이 바뀐 습관과 충돌하면요?

최근 30일·20건을 시간 가중해 승자를 고릅니다. 동률·승자 변경은 기존 기억을 강등하고, 거절된 Intent는 새 증거 3건 전까지 재제안하지 않습니다.

## 같은 몸짓의 개인차도 보나요?

실측 시간·속도·진폭 embedding을 최근 승자 관찰 평균과 비교합니다. 고정 인코더이며 실제 분류 품질은 장비 검증이 필요합니다.

## 학습부터 hands-free인가요?

아닙니다. 반복과 최초 승인이 필요합니다. `open_palm:none`과 `circle:clockwise`로 승인·거절 및 직후 피드백을 할 수 있지만 콜드스타트 비용은 남습니다.

## 실제 앱을 제어하나요?

기본은 `DRY_RUN`입니다. OS 실행을 켜고 활성 창 확인을 통과하면 지원 앱에 키를 보냅니다. 절차는 [운영 가이드](operations.md)에 있습니다.

## 한계는 무엇인가요?

활동은 발표·음악 두 개, 활성 기억은 몸짓·활동당 하나입니다. 볼륨·줌만 진폭으로 1~5단계 실행하며 시퀀스·문법·인증·동기화는 지원하지 않습니다.
